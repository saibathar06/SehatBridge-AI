# Security model

Passwords use Argon2id. Access JWTs have a 15-minute default lifetime with issuer, audience and session-version validation. Refresh tokens are random, server-side HMAC hashed, rotated on use and revoked on replay. Replay revokes the user's session family. Logout/password reset increments the session version and revokes refresh tokens. The app keeps only its refresh credential in Expo SecureStore; access credentials are memory-only. Backend secrets never belong in an Expo public variable.

OTP codes are cryptographically generated, purpose-bound and HMAC stored, with 10-minute expiry, single use, five attempts and 60-second resend cooldown. IP and destination/account rate limits apply. Production startup refuses console delivery, SQLite and missing Redis. Console OTP output is intentionally restricted to development. SMTP uses STARTTLS; configure a delivery account and approved sender.

Google reCAPTCHA v2 checkbox protection is available for registration, login and OTP email requests. The native client loads an isolated backend-hosted checkbox page and submits its short-lived token; the backend verifies it with Google and checks the exact hostname before side effects. Production requires valid CAPTCHA configuration; development may explicitly disable it until keys are supplied. Google errors fail closed. Keys, domain setup, mobile message/navigation restrictions and remaining live-device verification are described in [reCAPTCHA setup](recaptcha.md).

Medical JSON columns and files use AES-256-GCM, random 96-bit nonces, and table/owner or file/owner associated data. Email addresses are separately encrypted and looked up using a keyed HMAC. Keys are supplied by environment and never stored in PostgreSQL. The authorized backend holds the key and can read plaintext during processing. This protects a database-only exposure; it does not protect against a fully compromised backend or compromised device.

Use a managed secret/KMS envelope system, private encrypted disks, database encryption, TLS between services and encrypted backups for deployment. Current application-level encryption uses one configured key; key rotation must re-encrypt live data and retained backups under a versioned-key migration. Do not replace the key without migrating existing data. Losing it makes records unreadable.

Patient endpoints derive ownership from the verified JWT and query by both record ID and user ID. Unrelated records return 404. Foreign keys cascade deletion across treatment data; unique constraints protect page positions, source confirmations, dose generation, idempotency keys and demo slot reservations. PostgreSQL row locks provide the production concurrency path. SQLite is only a development/test convenience.

Uploads have request/group/file/page limits, chunked-body limits, file-signature checks, image decoding/pixel limits, PDF parsing, encryption and generated UUID storage paths. No client filename is used as a filesystem path. PDF previews render privately in backend memory. Files are not publicly mounted. Source endpoints use authentication and no-store headers. Deploy parser/model workloads behind container memory/CPU limits and an ingress body/request timeout; hostile PDFs still require ongoing parser updates and deployment-level isolation.

No medical text, transcripts, API keys, tokens, passwords or provider error payloads are written to ordinary logs. Audit rows contain action, resource ID and timestamp only. Disable reverse-proxy request-body logging and redact authorization headers. Unexpected errors return generic responses; validation errors omit submitted values. Provider failures retain a sanitized recoverable document status.

Restrictive CORS is empty by default for native clients. Configure explicit browser origins only if a future authorized client requires them. Terminate HTTPS at a trusted gateway. Release mobile builds refuse an HTTP backend. Development LAN HTTP should use synthetic documents only.

Account deletion immediately removes live records and files after processing stops. Configure and communicate an explicit encrypted-backup retention policy before use with real patient data. Deleting documents also deletes associated plans and doses; device queues are cancelled at next successful reconciliation. Other signed-in devices must reconnect to observe changes. Existing OS notifications cannot be remotely guaranteed erased from an offline device.

Third-party Gemini and device speech privacy terms apply. The UI asks for document AI consent and explains permissions. Chat history is opt-in, encrypted, clearable and deleted when disabled. No verified medicine reference is installed; safety questions fail closed instead of generating a side-effect list. No claim of medical accuracy, regulatory compliance or production certification is made.
